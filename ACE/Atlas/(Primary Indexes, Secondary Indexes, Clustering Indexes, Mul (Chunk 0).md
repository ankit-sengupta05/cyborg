(Primary Indexes, Secondary Indexes, Clustering Indexes, Multilevel Indexes, Dynamic Multilevel Indexes Using B-Trees and B+-Trees) 1. Multi-Level Index Multi-level indexing is used to improve search efficiency. Index is created on another index, forming multiple levels. It reduces disk access and improves performance. Advantages: - Faster data retrieval - Reduced search space - Efficient for large databases B-Tree and B+ Tree – Detailed Notes with Multiple Examples B-Tree Insertion Rules Insert keys in sorted order Each node can have max (m − 1) keys If node is not full → insert directly If node is full (overflow): Find middle key Move middle key to parent Split into left (small) and right (big) If parent also full → repeat split If root splits → new root is created Data stored in both internal and leaf nodes 🌳 B+ Tree Insertion Rules Insert only in leaf nodes Keys are always in sorted order Each node can have max (m − 1) keys If leaf is not full → insert directly If leaf is full (overflow): Split node into two Promote key to parent (copy) Right-side method: Promote first key of right node Left-side method: Promote last key of left node If parent overflows → split again Leaf nodes are linked Data stored only in leaf nodes 2. B-Tree Theory B-Tree is a self-balancing tree used in databases and file systems. It maintains sorted data and allows searches, insertions, and deletions in logarithmic time. Properties: - Maximum children = m - Maximum keys = m-1 - Minimum keys = ceil(m/2)-1 - All leaves are at same level - Tree is always balanced - On overflow → split and promote middle key EXAMPLE: - Insert 5, 3, 21, 9, 1, 13, 2, 7, 10, 12, 4, 8 of order 4 EX:- Insert: 10, 20, 5, 6, 12, 30, 7, 17 of order 4 B-Tree Example 1 (Order 3) Insert: 10, 20, 5, 6, 12 [10] [10 20] Split → [10] [5] [20] Insert 6 → [5 6] Insert 12 → [12 20] B-Tree Example 2 (Order 4) Insert: 15, 25, 5, 10, 20, 30 [15] [15 25] [5 15 25] Overflow → split → [15] [5 10] [25] Insert 20, 30 → [15] [5 10] [20 25 30] B-Tree Example Deletion: 10, 20, 5, 6, 12, 30, 7, 17 of order 4 Let’s solve it step by step: first build the B-Tree (order 4), then perform deletion. 👉 Order = 4 ⇒ Max children = 4 Max keys = 3 Min keys = 1 (except root) 🌳 Step 1: Insert all keys Keys: 10, 20, 5, 6, 12, 30, 7, 17 Insert 10, 20, 5 [5, 10, 20] Insert 6 → ❌ Overflow (4 keys) Split: [10] / \ [5,6] [20] Insert 12 [10] / \ [5,6] [12,20] Insert 30 [10] / \ [5,6] [12,20,30] Insert 7 [10] / \ [5,6,7] [12,20,30] Insert 17 → ❌ Overflow Split right child: [10, 20] / | \ [5,6,7] [12,17] [30] ✅ Final B-Tree after insertion [10, 20] / | \ [5,6,7] [12,17] [30] 🧹 Now Deletion (example: delete 6) Step 2: Delete 6 [10, 20] / | \ [5,7] [12,17] [30] ✔ No underflow (min = 1) Step 3: Delete 7 [10, 20] / | \ [5] [12,17] [30] ✔ Still valid Step 4: Delete 5 → ❌ Underflow Left node becomes empty 👉 Borrow from sibling [12,17] [12, 20] / | \ [10] [17] [30] ✅ Final Tree after deletions [12, 20] / | \ [10] [17] [30] 3. B+ Tree Theory B+ Tree is an advanced version of B-Tree. All actual data is stored only in leaf nodes. Internal nodes store only keys. Leaf nodes are connected (linked list). Advantages: - Faster search - Efficient range queries - Sequential access is easy EXAMPLE: - Insert 5,10,12,15,6,21,45,36,65,14 of order 4 Insert 1,4,7,10,17,21,31,25,19,20,28,42 of order 4. Insert: 5, 15, 25, 35, 45, 30 of order 3 10, 20, 5, 6, 12 (Order = 3) B+ Tree Example Insert: 10, 20, 5, 6, 12 [10] [10 20] Split → parent [10] Leaves: [5 10] [10 20] Insert 6 → [5 6 10] Insert 12 → split and adjust B+ tree Insert: 5, 15, 25, 35, 45, 30 of order 3 Step 1: Insert 5 Tree is empty → create root [5] Step 2: Insert 15 Insert in same leaf (sorted) [5, 15] 🌳 Step 3: Insert 25 → ❌ Overflow Max keys = 2 → now 3 keys → split Split into two leaf nodes Middle value (15) goes to parent [15] / \ [5] [15,25] ✔ In B+ Tree, leaf keeps duplicate (15) 🌳 Step 4: Insert 35 Go to right leaf [15] / \ [5] [15,25,35] ❌ Overflow → split 👉 Split leaf 👉 Promote 25 to parent [15, 25] / | \ [5] [15] [25,35] 🌳 Step 5: Insert 45 Go to rightmost leaf [15, 25] / | \ [5] [15] [25,35,45] ❌ Overflow → split 👉 Promote 35 [15, 25, 35] / | | \ [5] [15] [25] [35,45] ❌ Parent overflow → split again New root created [25] / \ [15] [35] / \ / \ [5] [15] [25] [35,45] 🌳 Step 6: Insert 30 Go to right subtree → then left leaf of it [25] / \ [15] [35] / \ / \ [5] [15] [25,30] [35,45] ✔ No overflow → Done Final B+ Tree [25] / \ [15] [35] / \ / \ [5] [15] [25,30] [35,45] Leaf Node Linking (Important) [5] → [15] → [25,30] → [35,45] What is B+ Tree Deletion? Remove a key from a leaf node Maintain: Minimum keys condition Balanced structure Leaf node links ⚙️ Rules (Order = 3) Max keys = 2 Min keys = 1 (except root) 🔄 Deletion Algorithm (Steps) 1️⃣ Find the key Traverse from root → reach correct leaf node 2️⃣ Delete the key Remove key from leaf 3️⃣ Check underflow If keys ≥ min → ✅ Done If keys < min → ❌ Fix needed ❌ Underflow Handling 🔹 Case 1: Borrow from sibling Check left or right sibling If sibling has extra key, borrow 👉 Adjust parent key also 🔹 Case 2: Merge (if no borrowing possible) Merge with sibling Remove key from parent 🔹 Case 3: Parent underflow If parent becomes empty → repeat process upward 🔹 Case 4: Root becomes empty Make child as new root Height decreases B-TREE-DELETION 📌 Example (Order 3) Initial tree: [15, 35] / | \ [5] [25,30] [45] 🧹 Delete 30 [15, 35] / | \ [5] [25] [45] ✔ No problem (min = 1) Delete 25 → Underflow Middle node becomes empty 👉 Borrow from left or right? Left has 1 (can’t give) Right has 1 (can’t give) Merge with left [35] / \ [5,15] [45] Delete 45 [35] / \ [5,15] [] ❌ Underflow → merge [5,15,35] 👉 Root adjusted ✅ Final Tree [5,15,35] B+TREE DELETION B+ Tree Deletion? When you delete a key: Remove from leaf node Check minimum occupancy If underflow: Borrow (Redistribute) from sibling OR Merge with sibling Update parent keys if needed Example 1: Simple Deletion (No Underflow) Given B+ Tree (Order = 3) (Max children = 3 → Max keys = 2, Min keys = 1) [20] / \ [5,10] [20,30] Delete: 10 👉 After deletion: [20] / \ [5] [20,30] ✔ No underflow (min = 1 key → OK) ✅ Example 2: Deletion with Borrow (Redistribution) Before Deletion: [20] / \ [5] [20,30] Delete: 5 👉 Left node becomes empty ❌ (underflow) Borrow from Right Sibling: Right sibling has 2 keys → can share 👉 After Redistribution: [30] / \ [20] [30] ✔ Parent updated (20 → 30) ✅ Example 3: Deletion with Merge Before: [20] / \ [5] [20] Delete: 5 👉 Left node becomes empty ❌ 👉 Right sibling has only 1 key → cannot borrow Merge Nodes: [20] | [20] 👉 Parent node becomes unnecessary → removed Final Tree: [20] ✅ Example 4: Bigger Tree Deletion Initial Tree (Order = 3) [20,40] / | \ [5,10] [20,30] [40,50] 🔴 Delete: 10 [20,40] / | \ [5] [20,30] [40,50] ✔ No problem 🔴 Delete: 5 👉 Underflow in first node 👉 Borrow from middle node [30,40] / | \ [20] [30] [40,50] 🔴 Delete: 20 👉 Underflow again 👉 Merge with sibling [40] / \ [30] [40,50] Key Rules to Remember ✔ Always delete from leaf node ✔ Maintain minimum keys = ⌈(m-1)/2⌉ ✔ Try borrow first, then merge ✔ Update parent separator keys ✔ Internal nodes store copies of keys, not actual data 4. Difference Between B-Tree and B+ Tree B-Tree: - Data stored in all nodes - Search can end at internal node B+ Tree: - Data stored only in leaf nodes - Faster and efficient for range queries Placing File Records on Disk 👉 It means how records are stored on disk in a database. There are three main methods: ✅ 1. Heap File Organization 🔹 Idea Records are stored randomly (no order). 🔹 Working New records are added at the end No sorting is followed 🔹 Example 25 10 35 20 🔹 Advantages ✔ Fast insertion 🔹 Disadvantages ❌ Slow searching (need to check all records) ✅ 2. Sequential File Organization 🔹 Idea Records are stored in sorted order. 🔹 Working Data is arranged (e.g., ascending order) Searching is faster (binary search possible) 🔹 Example 10 20 25 35 🔹 Advantages ✔ Fast searching 🔹 Disadvantages ❌ Insertion is slow (need to place in correct position) ✅ 3. Hashing File Organization 🔹 Idea Use a hash function to decide where to store data. 🔹 Working Apply a formula like: 👉 h(key) = key % 10 It gives a direct location 🔹 Example 25 → 5 10 → 0 0 → 10 5 → 25 🔹 Advantages ✔ Very fast searching ✔ Fast insertion 🔹 Disadvantages ❌ Collision may occur (two keys map to same location) ✅ Comparison ✅ Final One-Line Answer (Exam) Heap stores records randomly, sequential stores them in sorted order, and hashing uses a hash function to directly locate records for fast access.
